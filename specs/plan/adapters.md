# Source adapters and paste parser (`@cb/adapters`)

Adapters run as content scripts in the user's tab, only after a click. They read the visible DOM
and return a `Transcript` or a `CaptureError`. They never fetch, except images already displayed.

## Interface
```ts
type CaptureError = { code: "capture_empty" | "unsupported_page" | "parse_failed"; message: string };
interface SourceAdapter {
  id: string;                          // "gemini" | "chatgpt" | "generic"
  version: string;                     // "0.1"; bump when selectors change
  matches(url: URL): boolean;
  capture(doc: Document, opts?: { selection?: Selection }): Promise<Transcript | CaptureError>;
}
function pickAdapter(url: URL): SourceAdapter;   // structured adapter if matches, else generic
```

## Structured adapters (Gemini, ChatGPT)
- Selectors live in one versioned object per adapter (`selectors.ts`). Strategy: stable semantic
  attributes first (`data-*`, `role`, ARIA), structural fallback second. No class names generated by
  build tools.
- **Written only against saved fixture HTML** in `packages/adapters/fixtures/<adapter>/*.html`,
  created by the human from a chat with synthetic content. The agent never guesses the live DOM.
- Part mapping: `pre > code` → `code` (language from a `language-*` class or header label; content
  via `textContent`, which preserves whitespace) · `table` → `table` (converted to Markdown) ·
  KaTeX/MathJax annotation → `math` · links in answers → `citation` · images and file chips →
  `attachment` · everything else → `text` via `innerText`.
- Only the followed branch: when a turn shows "2 / 3" variants, capture the visible one.
- Validation: ≥ 1 user turn, no empty parts. Otherwise a `CaptureError` (AC-04).
- Lazily loaded history: capture what is in the DOM and add a warning with the turn count.

## Generic adapter (any site, AC-02)
- Input: the user's current text selection (passed in from a context-menu click).
- Splits the selection's top-level blocks into turns. If blocks alternate in a repeated structure,
  roles alternate starting with `user`; otherwise one `user` turn.
- Code blocks from `pre` elements are kept as `code` parts.
- `confidence: "inferred"`, `adapter: "generic@0.1"`, warning "roles inferred".

## Page images
For each image in a turn: try `fetch(img.src)` from the content script (works for `data:`, `blob:`
and same-origin URLs). On failure (cross-origin), create the attachment with `status: "listed"`,
`reason: "not readable from the page; drop the original to include it"`. No extension privileges
are used to bypass CORS (decision recorded in `decisions.md`).

## Paste parser (AC-03)
- Role markers at line start, case-insensitive, followed by `:`: `User`, `You`, `Me` → user;
  `Assistant`, `ChatGPT`, `Gemini`, `Claude`, `Model`, `AI` → assistant.
- Fenced code blocks (```` ``` ````) become `code` parts; Markdown tables become `table` parts.
- No markers: one `user` turn plus warning "no roles found".
- `adapter: "paste@0.1"`, `confidence: "inferred"`.
- Signature: `parsePaste(text: string, opts?: { title?: string }): Promise<Transcript | CaptureError>`.
  Async because turn hashes use WebCrypto (`sha256HexWeb`); it runs in the extension panel, so
  `@cb/adapters` imports no `node:` module. Empty or whitespace-only text → `capture_empty`.

## Fixture rules
- Fixture HTML must contain only synthetic content. Strip `<script>` tags and inline tracking
  attributes before saving. Keep the conversation container's outerHTML.
- Each fixture has an expected transcript JSON next to it (`chat-01.expected.json`) written by hand
  from what the page visibly shows. Tests compare adapter output against it.
